# 第三题 简短说明（Redis 学习信息与排行榜）

键前缀 `exam:12403030110:`，运行于三主三从 Redis Cluster（127.0.0.1:7000~7005，redis-py `RedisCluster` 客户端）。

## 实测结果
1. **学生信息（Hash `...:student`）**：`studentId=12403030110`、`name=张三`、`className=124030301`、`courseId=COURSE-12403030110-01`、`status=learning`；`HSET status completed` 后单独 `HGET name`=张三、`HGET status`=completed，`HGETALL` 显示其余字段全部保留。
2. **已完成章节（Set `...:chapters:done`）**：依次提交 CH01/CH02/CH02/CH03，SCARD 依次为 1→2→2→3；最终成员 CH01、CH02、CH03；`SISMEMBER CH02`=True、`CH04`=False；再次提交 CH02 新增成员数 0、数量仍为 3（去重生效）。
3. **排行榜（ZSet `...:rank`）**：初始 `Student:12403030110=70+C=70`、demo:01=85、demo:02=90、demo:03=60、demo:04=80；前 3 名为 demo:02(90)、demo:01(85)、demo:04(80)。`ZINCRBY 20` 后本人 90 分，再次前 3 名为 demo:02(90)、Student:12403030110(90)、demo:01(85)；降序位置（0 起）=1 → **第2名**（同分按成员字典序，不采用并列名次）。
4. **会话（String `...:session`，EX=5）**：创建后键值 `session-12403030110-abc`、TTL=5；等待 6 秒后 `EXISTS`=0、`TTL`=-2，**过期验证通过**。
5. **类型核验**：student=`hash`、chapters:done=`set`、rank=`zset`、session=`string`（在过期前检查并记录）。

## 数据类型选择理由
- **Hash**：学生信息是「字段—值」集合，可按字段读写与局部修改，新增字段不影响其他字段，避免整体序列化后覆盖写。
- **Set**：已完成章节必须去重且频繁判断"是否已完成"，Set 天然去重并支持 O(1) `SISMEMBER`，也可用 `SINTER` 做章节进度对比。
- **ZSet**：排行榜需要按分数排序并取前 N 名、还要对个人分数做增量更新，`ZREVRANGE` 直接取降序前 N，`ZINCRBY` 原子加分，名次由 `ZREVRANK` 给出。
- **String**：会话只保存一个标识值，配合 `EX` 由 Redis 自动删除，是实现"到点失效"最轻量的结构。
